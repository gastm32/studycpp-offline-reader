# C++ `<algorithm>` 知识点与面试题汇总

## 一、 当前文件夹本地知识点回顾（基础篇）

根据 `18_第十八章 迭代器与算法` 中的内容，标准库算法通常分为三类：查看、修改和辅助。常见的有：

### 1. 查找与计数
- **`std::find`**: 按值查找，返回指向第一次出现的迭代器。如果没找到，返回 `end()`。
- **`std::find_if`**: 按条件查找，接收一个可调用对象（如函数或 Lambda），遇到第一个使得条件为 `true` 的元素时返回。
- **`std::count` / `std::count_if`**: 统计特定元素或满足特定条件的元素个数。

### 2. 排序与遍历
- **`std::sort`**: 对范围内的元素进行排序（默认升序）。可以通过传入自定义的比较函数（如 `std::greater{}` 或 Lambda 表达式）作为第三个参数来实现降序或针对自定义类的排序。
- **`std::for_each`**: 对序列中的每个元素执行特定操作。相比于范围 `for` 循环，它的意图更明确，能避免意外的局部变量引用错误，也容易实现跳过开头元素等操作（结合 `std::next`）。

### 3. 语法糖：C++20 Ranges
- 传统算法需要传入 `begin()` 和 `end()` 两个迭代器，在 C++20 中引入了 Ranges 库，可以直接传入容器：`std::ranges::sort(arr)`，大大简化了代码。

## 二、 笔试/面试高频扩展与避坑（进阶篇）

在秋招和笔试中，关于 `<algorithm>` 不仅会考怎么用，还会考底层原理。

### 1. 迭代器类型的限制（必考！你做错过的题目）
**考点**：`std::sort` 为什么不能给 `std::list` 排序？
- **原因**：`std::sort` 底层依赖快速排序，需要能够“瞬间跳转到中间”的能力。也就是说，它要求容器提供 **随机访问迭代器 (Random Access Iterator)**。
- **结论**：`std::vector`、`std::deque`、`std::array` 可以用 `std::sort`。而 `std::list` 底层是双向链表，只能逐个顺藤摸瓜，不支持随机访问，所以必须用自带的方法 `list.sort()`。

### 2. `std::sort` 的底层原理到底是什么？
**面试题**：`std::sort` 就是快速排序吗？
- **答案**：不完全是。在主流 STL 实现中，它采用的是 **IntroSort（内省式排序）**。
- **运行机制**：
  1. 默认使用**快速排序**，保证绝大多数情况下的平均极快速度。
  2. 当递归深度过深（可能面临恶化为 $O(N^2)$ 的最坏情况）时，自动切换为**堆排序**（保证最坏情况的复杂度仍为 $O(N \log N)$）。
  3. 当分割后的子序列元素很少（如 16 个以下）时，切换为**插入排序**（因为在小数据量下，插入排序的常数开销比快排小得多）。

### 3. 二分查找系列（经常被混淆）
**面试题**：`lower_bound` 和 `binary_search` 有什么区别？
- **`std::binary_search`**：仅仅告诉你“存在”或“不存在”（返回 `bool`）。
- **`std::lower_bound`**：返回第一个 **大于或等于** 目标值的元素的迭代器。如果你想在有序数组中找个位置把新元素插进去，用这个。
- **`std::upper_bound`**：返回第一个 **大于** 目标值的元素的迭代器。

### 4. 经典的 Erase-Remove 惯用法
**面试题**：如何删除 `vector` 中所有值为 `x` 的元素？
- **易错点**：直接使用 `std::remove` 并没有真正删掉元素！它只是把保留下来的元素往前挪，然后返回一个新的“逻辑末尾”，容器的 `size` 并未改变。
- **正确做法**：必须配合容器的 `erase` 函数来销毁多余的尾部空间，这叫做 `erase-remove idiom`：
  ```cpp
  vec.erase(std::remove(vec.begin(), vec.end(), x), vec.end());
  ```
  *(注：在 C++20 中，可以直接写 `std::erase(vec, x);`，变得非常方便)*

### 5. 稳定排序与局部排序
- **稳定排序**：如果需要保持相等元素的原始相对顺序，应使用 `std::stable_sort`，其底层一般是归并排序，但需要额外的内存开销。
- **Top K 问题**：如果只需要找出前 K 个最大的元素，不要直接全量 `sort`。使用 `std::partial_sort` 可以只对局部进行排序，或者使用 `std::nth_element`，效率更高。
