# C++ 阶段性测试卷 (第1-18章) - 错题与核心知识点解析

## 第 1 题：指针与引用的区别
**题目：** 关于指针和引用的区别，以下说法错误的是？
A. 指针可以为空 (nullptr)，而引用必须在定义时初始化并绑定到一个有效的对象。
B. 指针可以随时改变所指向的地址，引用一旦绑定到一个对象就不能再改变。
C. 引用实质上是一个常量指针，但在使用上不需要显式使用解引用操作符 (`*`)。
D. 使用 `sizeof(引用)` 得到的是“引用这个变量本身”所占的内存大小，而不是它所绑定对象的大小。

**正确答案：** D
**你的答案：** D (附言：A是什么？其实都不太懂)

**【知识点深度解析】：**
这道题选 D 是因为 D 的说法是**错误**的。在 C++ 中，引用只是另一个对象的“别名”，所以对引用进行 `sizeof` 操作，得到的完全是**它所绑定的那个对象的大小**，而不是引用本身（或者说底层指针）的大小。

针对你问的 A 选项（“A是什么？”），这里彻底理清**指针 (Pointer)** 和 **引用 (Reference)** 的核心区别：
1. **关于是否可以为空 (A选项，说法正确)**：
   - **指针**：就像一张写着地址的纸条。纸条上可以什么都不写（在 C++ 中叫 `nullptr`，即空指针），表示它现在不指向任何地方。
   - **引用**：就像是给一个人起的外号。你不能给“不存在的人”起外号。所以，引用在创建的第一时间，就**必须**绑定到一个确实在内存中存在的变量上。
2. **关于是否可以改变绑定 (B选项，说法正确)**：
   - **指针**：纸条上的地址你可以擦掉，重新写另一个地址（改变指向）。
   - **引用**：外号一旦送给某人，就终身绑定了。你不能在代码中让一个引用半路去代表另一个变量。
3. **底层原理 (C选项，说法正确)**：
   - 在编译器底层，引用其实就是用“常量指针（一旦指向某处就不准改的指针）”来实现的，只是 C++ 语法帮你隐藏了繁琐的 `*`（解引用）符号，让你用起来更像普通的变量。

## 第 2 题：高效的参数传递
**题目：** 将一个包含 10 万个元素的 `std::vector<int>` 传递给一个只负责读取和打印数据的函数，以下哪种参数声明方式最合适、最高效？
A. `void printData(std::vector<int> vec)` (按值传递)
B. `void printData(std::vector<int>* vec)` (按指针传递)
C. `void printData(const std::vector<int>& vec)` (按 const 引用传递)
D. `void printData(std::vector<int>& vec)` (按普通引用传递)

**正确答案：** C
**你的答案：** C

**【知识点深度解析】：**
这是 C++ 中最常用的性能优化技巧！
- **错在 A**：按值传递会触发“拷贝”。把 10 万个整数完完整整复制一份传给函数，极其消耗时间和内存。
- **错在 D**：普通的引用 `&` 相当于把原数据的控制权交给了函数，函数内如果不小心修改了数据，外面的原数据也会跟着变。既然题目说“只负责读取和打印”，这就存在安全隐患。
- **错在 B**：传指针虽然高效，但调用时需要写 `&` 取地址，内部还要用 `->`，语法繁琐，且指针可能是空指针（引发崩溃），不够安全。
- **为什么选 C**：`const Type&`（常量引用）是完美的方案。**“引用”**保证了只传了一个地址进去（极快，零拷贝），**“const”**保证了函数内部绝对无法修改这个数据（极安全）。（牢记：传递大对象，优先用 `const &`）

## 第 3 题：复杂的 `const` 修饰符
**题目：** 关于 C++ 中的 `const` 修饰符，`const int* ptr` 和 `int* const ptr` 的含义分别是？
A. 前者是常量指针（指针本身不可变），后者是指向常量的指针。
B. 前者是指向常量的指针（不能通过指针修改值），后者是常量指针（指针指向的地址不可变）。
C. 两者都是指向常量的指针。
D. 两者都是常量指针。

**正确答案：** B
**你的答案：** B

**【知识点深度解析】：**
这是一个经典的面试题，因为 C++ 的 `const` 位置非常绕。教你一个终极口诀：**“从右往左读（或者看 const 在 `*` 的哪一边）”**。
- `const int * ptr`：`const` 在 `*` 的左边。表示指针指向的数据是 const（常量）的。你可以让 `ptr` 指向别的地方，但你不能通过 `*ptr = 5` 来修改那个地方的值。（门牌号可以换，但房间里的东西不准动）
- `int * const ptr`：`const` 在 `*` 的右边，紧贴着 `ptr`。表示指针本身（`ptr`）是 const（常量）的。你不能改变 `ptr` 的指向，但你可以通过 `*ptr = 5` 修改那里的值。（房间里的东西可以随便换，但你这辈子只能守着这个门牌号）

## 第 4 题：`std::vector` 的底层扩容机制
**题目：** 当 `std::vector` 的当前大小等于其容量，且需要继续添加新元素时，它在底层通常会怎么做？
A. 在原内存块的末尾直接追加分配一段新内存。
B. 抛出内存溢出（Out of Memory）异常。
C. 申请一块更大的新连续内存（通常是现在的 1.5 倍或 2 倍），将旧元素拷贝或移动过去，并释放旧内存。
D. 停止工作，强制要求程序员手动调用扩容函数。

**正确答案：** C
**你的答案：** C

**【知识点深度解析】：**
`std::vector` 被称为“动态数组”，它的核心特征是**内存必须是连续的**。
因为内存是一块连着的空间，当它被装满后，不可能直接在后面“硬挤”出一块新空间（因为后面的内存可能已经被别的程序占用了）。
所以它的真实操作非常“暴力”：
1. 找一块全新的、更大的连片空地（通常是原来容量的 1.5 倍或 2 倍）。
2. 把老房子里的东西全部搬家（拷贝或移动）到新房子。
3. 把老房子拆掉（释放旧内存）。
4. 在新房子里放进你要添加的新元素。

## 第 5 题：函数重载 (Overloading)
**题目：** 以下关于函数重载的说法，正确的是？
A. 可以仅仅通过不同的返回值类型来重载函数。
B. 函数重载要求函数名相同，且参数列表（参数类型、个数或顺序）必须有所不同。
C. 重载的函数必须在不同的作用域内定义。
D. 函数的默认参数完全不会影响函数重载的解析，可以随意使用。

**正确答案：** B
**你的答案：** B

**【知识点深度解析】：**
重载就是“同一个函数名，干不同的事”，比如 `print(int)` 和 `print(string)`。
编译器区分它们**唯一**的依据就是**参数列表**（参数的个数、或者类型、或者顺序不同）。
- **为什么 A 错**：不能仅仅依靠返回值来重载。想象一下如果你写了 `int get()` 和 `double get()`，当你在代码里写了一句 `get();` 时，编译器根本不知道你想要哪一个，因为它还没看到你把返回值赋给谁。

## 第 6 题：类的初始化列表
**题目：** 关于类 (Class) 的构造函数初始化列表，以下描述错误的是？
A. `const` 成员变量必须在初始化列表中进行初始化，不能在构造函数体内赋值。
B. 引用类型的成员变量必须在初始化列表中进行初始化。
C. 成员变量实际的初始化顺序，是完全由它们在**初始化列表中出现的顺序**决定的。
D. 对于类类型的成员变量，使用初始化列表通常比在构造函数体内部赋值效率更高。

**正确答案：** C
**你的答案：** 不知道

**【知识点深度解析】：**
在 C++ 类中，写构造函数有两种方式给成员赋值：
1. 在大括号 `{}` 里面赋值（实际上是先默认构造了一次，然后再重新赋值，效率低）。
2. 使用冒号 `:` 引出的**初始化列表**（这是真正的初始化，效率高）。

- **为什么 A 和 B 是对的**：前面第1题说过，**引用**和 **`const`常量** 必须在“出生”的那一刻就给初值。对于类的成员来说，“出生”的时刻就是初始化列表，一旦进了 `{}` 里，就已经晚了（算是重新赋值了），编译器会报错。
- **为什么 C 是错的（考点）**：C++ 规定，不管你把初始化列表的顺序写成什么样，**成员变量在内存中初始化的真实顺序，只跟它们在类里面声明的上下顺序有关**！这是一个常考的坑，如果你的初始化存在依赖关系，顺序写错了就会引发重大 Bug。

## 第 7 题：`std::array` vs C风格数组
**题目：** `std::array` 和 C 风格数组 (`int arr[10]`) 的主要区别是什么？
A. `std::array` 长度可以动态改变，C 风格数组不行。
B. `std::array` 传递给函数时不会隐式退化为指针，且内置了 `size()` 方法可以知道自身的大小。
C. `std::array` 的内存强制分配在堆 (Heap) 上，C 风格数组在栈 (Stack) 上。
D. 它们没有任何区别，`std::array` 只是 C 风格数组的别名。

**正确答案：** B
**你的答案：** A 

**【知识点深度解析】：**
- **你选 A 的误区**：你把 `std::array` 和 `std::vector` 搞混了。在 C++ 里：
  - `std::vector` 是长度可以**动态改变**的数组。
  - `std::array` 和 C风格数组一样，是**固定长度**的，定义了 10 个空间，就永远是 10 个，不能增加。
- **那为什么还要发明 `std::array` 呢？（B 是对的）**：
  传统的 C 数组（比如 `int arr[10]`）非常糟糕，一旦把它传给一个函数，它就会“退化”成一个孤零零的指针（只保留了首地址），函数内部根本不知道这个数组有多长，极易发生数组越界。
  而 `std::array` 是一个经过封装的现代 C++ 类，它传给函数时非常安全，你随时可以调用 `arr.size()` 问它有多长。

## 第 8 题：`static` 局部变量的魔法
**题目：** 在 C++ 中，函数内部的 `static` 局部变量有什么特性？
A. 每次调用该函数时，它都会被重新初始化一次。
B. 它的作用域限制在该函数内部，但它的生命周期贯穿整个程序的运行过程，只被初始化一次。
C. 它可以在函数外部被随意访问，只要使用了 `extern` 关键字。
D. 它的存储位置与普通的局部变量完全相同，都在栈区。

**正确答案：** B
**你的答案：** B

**【知识点深度解析】：**
把 `static` 写在函数内部的变量前，它就拥有了“两面性”：
1. **从外面看（作用域）**：别人看不见它，它只属于这个函数内部。
2. **从里面看（生命周期）**：它其实是长生不老的。函数执行完毕，普通变量都被销毁了，但 `static` 变量不会死。下次再调用这个函数时，它会保留着上一次执行完留下来的值。
（应用场景：比如你想记录某个函数被调用了多少次，在里面写个 `static int count = 0; count++;` 简直完美。）

## 第 9 题：迭代器失效 (Iterator Invalidation) 的噩梦
**题目：** 使用迭代器遍历 `std::vector` 时，如果在循环内部调用了 `vec.push_back()` 添加新元素，可能会引发什么问题？
A. 迭代器会自动更新，安全地指向下一个元素，没有任何问题。
B. 可能会导致原迭代器失效 (Iterator Invalidation)，继续使用会引发未定义行为。
C. 新元素一定会被添加到当前迭代器指向的位置。
D. 编译器会报错，禁止在遍历时调用 `push_back`。

**正确答案：** B
**你的答案：** D (附言：不懂)

**【知识点深度解析】：**
这题非常关键，这是新手写 C++ 最容易写出的严重 Bug 之一。
- **为什么 D 错**：C++ 编译器并不“聪明”，它非常信任你。你边遍历边添加，编译器**不会报错**，它允许你这么写。
- **为什么 B 对**：结合我们**第 4 题**讲的底层机制！当你调用 `push_back()` 加数据时，万一 `vector` 的容量不够了怎么办？它会触发**搬家机制**！把所有数据搬到了新内存，并把旧内存拆了。
  但是，你手里用来遍历的**迭代器 (Iterator)**，其实底层就是个指针，它**依然傻傻地指着原来的旧内存地址**！这时候你再通过迭代器去访问元素，就等同于访问已经被系统回收的垃圾内存，程序直接崩溃，这就是臭名昭著的“迭代器失效”。

## 第 10 题：为什么要用 `static_cast`？
**题目：** 相比于 C 风格的强制类型转换 (如 `(int)3.14`)，为什么 C++ 更推荐使用 `static_cast`？
A. `static_cast` 编译后的执行速度更快。
B. `static_cast` 可以在不同类型间随意转换，比如把 `int` 强转为 `std::string`。
C. `static_cast` 会在编译时进行必要的类型安全检查，且在代码中更容易被搜索和识别，降低出错风险。
D. 两者在安全性上没有任何区别，仅仅是代码规范的不同。

**正确答案：** C
**你的答案：** C

**【知识点深度解析】：**
C 语言的强转 `(类型)变量` 就像是一个蛮不讲理的暴君，无论多离谱的转换（比如把一个整数强行当作一个类的指针），它都会默默执行，然后导致程序在运行时爆炸。
C++ 发明了 `static_cast` 等几个专门的转换词：
1. **更安全**：如果两种类型完全八竿子打不着，编译器会直接报错，不允许转换。
2. **容易找**：在几十万行代码里，如果你想找出哪里发生了类型转换，搜 `(int)` 根本没法搜（到处都是括号），但搜 `static_cast` 一秒钟就能全部找出来，这在大型工程中极其重要。
